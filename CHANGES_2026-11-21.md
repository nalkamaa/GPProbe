# Muutokset (index.html)

## (2) Yhdistyneiden toistojen tunnistus
- Uudet: `detectMergedReps(reps, cfg)`, `splitCurveReps(curve)`, `historyMedianRom(liftKey)`, `mergedWarnText(m)`, `setRepCount(s)`, `setRepCountOverride(dateStr, setIdx, value)`, vakio `MERGED_ROM_FACTOR = 1.6`.
- Muokatut: `flagSuspectReps(reps, cfg, mergedInfo?)` (yhdistetty toisto = "epäilyttävä" -> pois VL/RQI/RIR/MVT-oppimisesta/L-V-profiilista/e1RM:stä/päivän suunnitelmasta), `analyzeSet` (palauttaa `mergedReps`, `mergedCount`; `perRep[i].merged`, `perRep[i].flags` sisältää `merged` -> CSV `rep_flags`), `buildVerdict`, `buildShortRestFinding`, `renderLiveSet` (uusi `#liveMergedWarn`), toistolistojen tunniste "yhdistetty", `buildSetAnalysisHTML` + `bindSetAnalysisActions` ("Korjaa toistomäärä"), kokonaissummat (`renderDoneSummaryCard`, tänään-lista, historia, `weeklyVolume`, sessioanalyysin yhteenveto, CSV `epley_1rm_kg`).
- Sääntö: ROM > 1,6 x muiden toistojen mediaani (sarja >= 3 toistoa), muuten > 1,6 x liikkeen 90 pv historian mediaani (>= 6 toistoa), muuten > 1,8 x `minRomCm`. Määrä-arvio: nopeuskäyrän (`trace.curve`) jako minimeistä (<= 0,05 m/s tai < 25 % huipusta, osan huippu >= 0,08 m/s, siirtymä >= 8 cm), muuten round(ROM / mediaani).
- Uusi tallennettu kenttä: `set.repCountOverride` (valinnainen, kokonaisluku 1-99). Toistokohtaista `rep.merged`-kenttää ei tallenneta, se lasketaan (`perRep[i].merged`).

## (3) Oma nopeuskustannus
- Uudet: `ownVelocityCost(exercise, dateStr, pct, minN)` -> `{cost, n, scope: 'today'|'28d'}` tai null, `setCostObservation(set, exercise)`, `OWN_COST_MIN_TAIL = 2`.
- Havainto/sarja = regressiokulmakerroin V_best-toistosta eteenpäin (>= 2 kelvollista toistoa V_best mukaan lukien), ei lämmittelyjä, ei yhdistettyjä/epäilyttäviä. Mediaani: tämän päivän sarjat (>= 2), muuten 28 pv sarjat +-7,5 % 1RM (>= 2). Välimuisti `workoutsSignature()`-avaimella.
- `computeDailyPlan`: kustannus = 0,75 x oma + 0,25 x malli, rajattu 0,015-0,12; `costSrc` suomeksi. Alle 2 havaintoa -> entinen malli/42 pv -yhdistelmä. Toistolaskenta siirretty sisäiseen `calcRepsFor(L)`:iin (repsVL, repsRIR, cap).
- `analyzeSet`: jos sarjassa < 2 kelvollista toistoa V_best:stä alkaen, kustannus = oma yhteinen kustannus (`costSource: 'own'`), muuten entinen laskenta. Uusi opts: `noOwnCost`, `dateStr`.

## (4) "+1 toisto ok" -vihje
- Uudet: `extraRepHint(a, count, targetReps)`, `liveExtraRepHint(targetReps)`, elementti `#liveExtraRepHint`.
- Ehto: ohjattu tila, tavoite täynnä, VL < 0,5 x raja, viimeisen toiston RIR >= 3 (piikkaus >= 2), toistoja < Prilepinin max/sarja (%1RM-rivi). Teksti: "✅ +1 toisto ok (VL 8 % / raja 20 %, RIR ~3, max N/sarja)".
- Automaattinen lopetus tavoitetoistoilla (BLE-käsittelijä) ohitetaan kun vihjeen ehdot täyttyvät; lisätoistot tallentuvat normaalisti ja ehdot arvioidaan joka toistolla uudelleen.
- Päivän suunnitelma: `remainingSets = ceil((volyymi - tehdyt toistot) / toistoa per sarja)` (myös autoregulaation `remSetsRaw`). `planRepsOf(x)` huomioi `repCountOverride`:n.

## (5) Toistoprogressio
- `computeDailyPlan` askel 4: tavoite perusvoima (myös jakson Kerääminen) + edellinen sessio OK (ei VL-ylityksiä, RQI >= 65, ei liian väsynyt) + edelliset toistot/sarja < Prilepin repsMax -> sama kuorma, toistot = min(edellinen+1, repsMax, repsVL, repsRIR). Muuten kuormaprogressio (+liftIncrement) kuten ennen; piikkaus/maksimivoima ennallaan.
- Palautus: `plan.progression {mode: 'reps'|'load', lastLoad, prevPerSet, loadAlt}`, `plan.alt {kind: 'load'|'reps', load, reps, sets}`. `planAltHTML(plan)` näyttää rivin "Vaihtoehto (kuormaprogressio|toistoprogressio): X kg × R × S" kompaktissa ja täydessä näkymässä.

## Oletukset / rajaukset
- Historian mediaani-ROM lasketaan liikeavaimella (squat/bench/deadlift), ei yksittäisen liikkeen nimellä.
- Yhdistyneille toistoille ei lisätä omaa CSV-saraketta; ne näkyvät `rep_flags`-sarakkeessa arvolla `merged`. `repCountOverride` ei ole CSV:ssä (sarakerakenne ennallaan), mutta `set_epley_1rm_kg` käyttää sitä.
- Ilman korjausta yhdistetty toisto jää pois päivän suunnitelman toistosummista (vain kelvolliset toistot lasketaan); korjaus tehdään "Korjaa toistomäärä" -kentällä tallennetun sarjan analyysissä.
- Raakadatan segmentointia (`analyzeTrace`) ei muutettu; jako tehdään vain jo tallennetun `trace.curve`:n päältä.
- Tavoite "bench ~5-6 toistoa" ei täyty tämän päivän datalla: oma kustannus ~0,028 -> VL-raja 20 % antaa 4 (squat 5, tai 4 kun >= 80 % 1RM Prilepin-katto).
- Ei selaimessa/BLE-laitteella testattu; testattu jsdom:lla CSV-datasta muunnetuilla sarjoilla.

Kyykky 21.11.: kuorma 127,5 kg = 79,5 % päivän e1RM:stä -> rivi 70-80 % (max 6), joten 5 toistoa on sallittu; >= 80 % raja olisi 4.
- Pienet: `detectMergedReps` karsii (n >= 3) referenssimediaanista ensimmäisen kierroksen kynnyksen ylittävät ROM:t (useita yhdistyneitä samassa sarjassa); `flagSuspectReps` laskee `medRom`:n ilman nolla-/puuttuvia ROM-arvoja ja yhdistettyjä toistoja.

## Kierros 3
- Yhdistyneiden toistojen tunnistus (`detectMergedReps`, `historyMedianRom`, `flagSuspectReps`):
  - Poistettu väärät hälytykset aiheuttanut varakynnys `1.8 * minRomCm`.
  - Kun `n === 2` ilman historiaa: verrataan sarjan kahta toistoa keskenään (`max / min > MERGED_ROM_FACTOR` ja `min >= minRomCm`).
  - Kun `n === 1` ilman historiaa: liputetaan yhdistyneeksi vain jos `trace.curve` jakautuu `splitCurveReps`:llä >= 2 toistoon.
  - Kun `n >= 3` mutta `others.length < 2`: sallitaan fallback `historyMedianRom`:iin.
  - `dateStr` välitetään `detectMergedReps(reps, cfg, dateStr)`, `flagSuspectReps(reps, cfg, mergedInfo, dateStr)` ja `historyMedianRom(liftKey, dateStr)` -funktioille; ROM-historia rajattu väliin `[dateStr - 90 pv, dateStr]` (B1-deterministisyys).
- Oma nopeuskustannus & autoregulaatio (`ownVelocityCost`, `computeDailyPlan`):
  - `ownVelocityCost` suodattaa myös `todayObs`:n `±7,5 % 1RM` -ikkunalla kun `pct > 0`, ja välittää `dateStr`:n `setCostObservation`:lle.
  - Estetty kesken treenin syntyvä väärä `missedReps`/`severeFatigue`-autoregulaatio: tavoitteensa puhtaasti täyttänyttä sarjaa (`targetReps` täynnä, ei VL-ylitystä, RIR >= 2) ei tulkita epäonnistuneeksi, eikä `reps` nouse kesken treenin yli jo tehtyjen puhtaiden työsarjojen.
- `+1 toisto ok` -vihje ja äänikehote (`playExtraRepVoiceCue`):
  - Generoitu rouhea suomenkielinen miesääni-MP3 (`assets/kevytta-viela-yksi-toisto.mp3`, `fi-FI-HarriNeural` `--pitch=-8Hz --rate=+14%` + lämmin rintarekisteri/saturaatiomasterointi: "Kevyttä, vielä yksi toisto!") ja upotettu base64 data-URI:na (`EXTRA_REP_VOICE_DATA_URI`) `index.html`:ään offline-toimintaa varten.
  - Kun `+1 toisto ok` laukeaa, `soundTargetReached()` ja `speakRepVelocity` ohitetaan, `keepWarmOsc` pysäytetään hetkeksi, `navigator.audioSession.type` vaihdetaan `'transient-solo'` (fallback `'transient'`) -tilaan musiikin keskeyttämiseksi puheen ajaksi, ja toiston päätyttyä/virheessä/turva-ajastimella palautetaan `'ambient'` ja käynnistetään `startAudioKeepWarm()` uudelleen jotta musiikki jatkuu. `SpeechSynthesis` (`fi-FI`, "Kevyttä, vielä yksi toisto!") toimii varajärjestelmänä.
  - `extraRepHint` vertaa `a.valid.length`:ää tavoitteeseen ja Prilepin-maksimiin eikä laukea päivän ensimmäisellä kartoittavalla viitesarjalla (`isReferenceSetContext`).
- Toistoprogressio & `planAltHTML`:
  - `calcRepsFor(lastLoad).cap > Math.round(prevPerSet)` tarkistetaan ennen `repMode = true` -lukitusta (estää jumitilanteen, esim. 25.11. penkki palaa kuormaprogressioon `90 kg × 3`).
  - `alt` (`kind: 'reps'`) tarjotaan `load`-tilassa vain kun `g.key === 'baseStrength'` ja `rr > Math.round(progression.prevPerSet)`.
  - `planAltHTML` käyttää yhtenäistä muotoa `${a.sets} × ${a.reps} @ ${a.load} kg` ja näyttää `Käytä`-painikkeen (`data-plan-apply`) kun `opts.withButtons` on true.
  - `firstWorkReps`-haara päivittää `volume = sets * reps` vain jos `Math.min(firstWorkReps, row.repsMax) > reps`.
- B1-viimeistely, `setRepCountOverride`, UI-johdonmukaisuus, `getAnchor1RM` ja välimuisti:
  - `dateStr` (ja tarvittaessa `profile`) välitetty puuttuviin `analyzeSet`-kutsuihin (`buildVbtSetBlockHTML`, `buildSetAnalysisHTML`, `renderDoneSummaryCard`, `renderLiveSet`, `renderRestSummaryCard`, `liveExtraRepHint`, `vbtOnNewRep`, `getRecentSameLoadHistory`, `calcVelocityDropPct`, `setCostObservation`).
  - `setRepCountOverride` säilyttää korjauksen arvoon `s.reps.length` silloin kun sarjassa on suspect/merged-toistoja.
  - `buildSetAnalysisHTML` laskee nopeus-/ROM-keskiarvot ja huiput kelvollisista toistoista (`setA.valid`), jos kelvollisia on >= 1.
  - `renderRestSummaryCard` näyttää `setRepCount(lastSavedSetRef)`-arvon kun `repCountOverride` on asetettu.
  - `getAnchor1RM` korjattu käyttämään `flagged.filter((x) => !x).length` (ei `!x.suspect`) ja huomioimaan `repCountOverride`.
  - `workoutsSignature()` sisältää nyt myös `vbtSettings.goal`, `vbtSettings.mvtOverride` ja `vbtSettings.cycle`.
